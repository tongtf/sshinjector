## 0. 铁律（每个任务都适用，违反即打回）

1. **测试先行**：实现代码与「新增/修改的测试」在**同一个提交**内；纯逻辑修复必须先有失败测试（红）再修（绿）。
2. **单一目的**：一个任务一个提交（Conventional Commits）；**禁止顺手重构**无关代码、禁止换行/格式化无关行。
3. **可回滚**：每个提交独立可 `git revert`；触不变量/行为变更的任务**必须**能单独回滚。
4. **不动不变量**：见 §6 不变量清单。触及不变量的任务在 PR 描述里写明「我如何证明没破坏它」。
5. **未实测不移除安全设施**：任何「删锁/删守卫/删兜底」必须先有通过的压力/并发测试证据（如 T-20）。
6. **行为变更显式声明**：T-12（门禁 fail-closed）、T-15（滑块范围）、T-11（首连日志）等对用户可见的变更必须写入发布说明并评估存量影响。
7. **提交前四道门全绿**（详见 §1）：`ktlintCheck` / `detekt` / `lint` / `testDebugUnitTest`。
8. **不引入新日志噪声**：新增日志遵守 `AGENTS.md`「应用内日志级别规范」——默认 `INFO`，异常显式定级，失败/丢弃类动态文案**必须传静态 `throttleKey`**，生命周期 INFO 保持默认 key。

## T-04 硬件密钥签名 blob【F-04 / audit #4、#5】

**目标**：`AndroidKeyStoreIdentity` 产出符合 SSH 规范的签名 blob：RSA=`string alg‖string sig`，EC 的曲线/摘要一致，Ed25519 用标准 JCA 名。

**触及**：`data/remote/ssh/AndroidKeyStoreIdentity.kt`。

**步骤**
- ☐ `getSignature(data)` → 转调 `getSignature(data, getAlgName())`。
- ☐ 覆写 `getSignature(data, alg)`，按 `privateKey.algorithm` 分派，**外层 `string alg` 用传入的 `alg`**。
- ☐ RSA：`rsaSignAlg(alg)`（`rsa-sha2-512`→`SHA512withRSA`，`rsa-sha2-256`→`SHA256withRSA`，`ssh-rsa`→`SHA1withRSA`）；组包 `writeString(alg)+writeString(rawSig)`。
- ☐ EC：keySize 用 `ECKey.params.order.bitLength()`（与 `getAlgName()` 同源）；`SHA384withECDSA` if >320 else `SHA256withECDSA`。
- ☐ Ed25519：`Signature.getInstance("Ed25519")`。
- ☐ 把 blob 组装抽成 `internal` 纯函数（不触 Keystore），供单测。

**自动验证**
- ☐ `rsa signature blob is string alg + string sig`：给定固定 `sig` 断言字节 == `putString("rsa-sha2-256")‖putString(sig)`。
- ☐ `rsa signature is not raw`：断言返回值长度 > 裸签名长度、且头部是 `00 00 00 0c`（"rsa-sha2-256" 长度）。
- ☐ `ec blob outer string equals negotiated alg`。
- ☐ `ed25519 blob outer string is ssh-ed25519`。
- ☐ `P-384 key uses SHA384withECDSA`（用真 `ECKey` 参数或抽出的 keySize 纯函数）。

**手工验证（真机，必需——Keystore 无法单测）**
- ☐ 生成 `ECDSA P-256` 密钥 → 连接成功（回归）。
- ☐ 生成 `RSA 2048` 密钥 → 连接成功（修复前必失败）。
- ☐ 生成 `ECDSA P-384` 密钥 → 连接成功（修复前若服务器严格校验曲线则失败）。
- ☐ 生成 `Ed25519`（若设备支持）→ 连接成功或明确报「设备不支持」，`logcat` 无 `Sign failed` 静默 null。

**监测**
- ☐ 保留 `Log.e("AndroidKeyStoreIdentity", "Sign failed: ...")`；新增失败时带上 `alg` 与 `algorithm`（便于区分是哪个密钥类型）。

**护栏（重要）**
- ☐ **不改** `getAlgName()` 对 RSA 返回 `ssh-rsa`（那是**公钥类型**，SSH 规范如此）。
- ☐ 不改 `buildEcdsaPublicKeyBlob`/`buildRsaPublicKeyBlob`（公钥 blob 语义不变）。
- ☐ 不启用/删除 `useLegacyEcdsaFormat` 逻辑（保持现状）。
- ☐ 若 `"Ed25519"` 在某些设备抛异常，**只**返回 null（现状），不抛穿 KEX。

**DoD**：4 类单测绿 + 真机 4 种密钥验证记录。
**回滚**：revert（老 RSA 本就不可用，回滚不劣化）。

## T-06 forceDisconnect 用 tryLock 配对【F-06 / audit #6】

**目标**：消除「`withTimeoutOrNull{lock()}` 可能获得锁后返回 null → 锁永不释放」的死锁风险。

**触及**：`vpn/SshVpnService.kt`（`forceDisconnect` + 新增 `acquireLockBounded`）。

**步骤**
- ☐ 删 `withTimeoutOrNull { connectMutex.lock(); true } ?: false`。
- ☐ 新增 `private suspend fun acquireLockBounded(windowMs: Long): Boolean`：循环 `connectMutex.tryLock()` → 成功 `true`；`delay(20)` 直到 `System.nanoTime()` 超窗口 → `false`（**未持有**）。
- ☐ `forceDisconnect`：`if (acquireLockBounded(...)) { try { teardownSession() } finally { connectMutex.unlock() } } else { 日志 + teardownSession() }`。

**自动验证**
- ☐ `forceDisconnect releases lock on success`：持锁计数在返回后为 0。
- ☐ `forceDisconnect does not leave lock held on timeout`：另一协程持锁 > 窗口 → `forceDisconnect` 返回后 `connectMutex.tryLock()` 成功（证明未泄漏）。
- ☐ `forceDisconnect unlocks exactly once`（计数器法）。

**手工验证**
- ☐ 断开卡 `Disconnecting` 超 3s 触发兜底 → 断开成功且**之后仍能重连**（证明锁未泄漏）。

**监测**
- ☐ 保留 `强制断开 · 会话锁被占用, 直接强拆 (最后手段)` 的 `WARNING`（`throttleKey="强制断开"`）。

**护栏**
- ☐ 不改变 `disconnect`/`disconnectInternal`/`autoReconnect` 的持锁结构（Mutex 不可重入纪律不变）。
- ☐ 不使用 `withLock` 包裹 `teardownSession`（它内部可能调 `forceReset`，需与非阻塞分支共存）。

**DoD**：3 单测绿 + 真机兜底路径验证。
**回滚**：revert。
