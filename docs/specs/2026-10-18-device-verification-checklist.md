# 真机核对清单 (无 adb · 只靠导出的应用内日志)

> 状态: 可用 (2026-10-18 建立; 同日三段真机日志回灌后补 S11 + "断开前强制一条快照")。
> 配套提交: 诊断面扩容 + 故障归因 (`feat(diag)`)、置 Established 唯一入口 (`refactor(tcp)`)、
> SSH 通道候选预算两层 + 坏会话后置 (`fix(ssh)`)、断开前快照 (`feat(diag)`)。
> 用途: 取代"自动化真机断言" —— 本机无 adb、无 profiler、无 tcpdump, 设备侧唯一的观测面是
> 应用内日志 (可复制/可导出). 因此把每条不变量写成 **"你做什么 → 日志里必须/不得出现什么"**。
> F-04 (连接对象化) 及后续任何触碰数据面的改动, 都以本文作为回归矩阵.

## 0. 为什么这份清单是"验收"而不是"建议"

改代码的人 (我) 拿不到设备; 拿得到设备的人 (你) 不该去读 Kotlin. 所以分工是:

- 我: 保证每条不变量都有一个**只能靠真机跑出来**的判据出现在日志里 (计数器/告警行), 并写进本清单;
- 你: 按场景跑一遍, 把导出的日志发我; 判据对不上就是失败, 不需要你判断为什么。

判据的三种形态:

| 形态 | 例子 | 判读方式 |
|---|---|---|
| **计数** | `数据面快照 · ... 零回程 0(秒断 0/迟断 0) ...` | 数字必须**不增长** (增量看两条快照之差) |
| **告警行** | `隧道侧零回程 · host:port — SSH 写出 517B / 读回 0B` | 出现即失败 (除非场景本身在故意制造) |
| **生命周期行** | `隧道通道就绪 ·a.com — 建连耗时 340ms` | 必须出现且耗时在阈值内 |

## 1. 操作回路

```bash
# 我这边 (本地构建, 你不需要 adb)
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
./gradlew assembleRelease         # 或 assembleDebug
# 产物: app/build/outputs/apk/{release,debug}/sshinjector-<版本>-<abi>[-debug].apk
#       (arm64-v8a 是绝大多数手机; 只给一个文件时传 arm64-v8a 那个)
```

1. 传到手机 (隔空投送/网盘) → 文件管理器点开安装。
   - **签名变了必须先卸载**: 从"每台机器各自的 debug key"切到共享 release key 后, 覆盖安装会
     报签名冲突。卸载会清 DB (服务器列表), 需要重新填 —— 一次性的。
   - 若手机上装过旧包: **先卸载再装**, 不要覆盖 (旧包签名不同装不上)。
2. 打开应用 → 设置 → **日志** → 右上角两个按钮:
   - 复制到剪贴板;
   - **导出到下载目录** → `<内部存储>/Download/sshinjector-log-<时间>.txt` (推荐, 完整)。
   - 日志页默认**隐藏 DEBUG**; 需要看每包级细节时点顶部 `DEBUG` chip 放行再导出。
3. 场景跑完后导出, 把 txt 发我 (或只发 `数据面快照` / `故障归因` / 含 `失败|异常|超时` 的行)。

**每次测试前**: 断开 → 重连一次, 让会话计数器从 0 开始 (见下节口径)。

## 2. 数字口径 (先把这一节看懂, 否则会误判)

| 数字 | 口径 | 说明 |
|---|---|---|
| `故障归因 · 本会话 N 类 M 次` | **本会话** | `connect()` 清零; 只统计 WARNING/ERROR (按节流后的行数, 看占比不看绝对量) |
| `数据面快照` 里的 TUN/回程/孤儿/零回程/闸门/背压/握手/上行缓存累计 计数 | **本会话** | `TcpStateMachine.reset()` 清零 (断开 / forceReset 两个会话边界); 这些是**累计量**, 只看增量 |
| `数据面快照` 的 `上行/下行` 字节与 `包 ↑↓` | **进程累计** | 用于算**两条快照之差** = 该分钟有没有在搬数据 |
| `SSH 会话 x/3` · `SSH IO 线程 a/b` · `在途通道` | **瞬时 gauge** | 看是否收敛, 不看累计 |
| `假 IP 映射 n/16384` · `待摘除` · `TUN 写队列 q` · `闸门等待 w` | **瞬时 gauge** | 同上 |
| `地址惰性失效 N` | **进程累计** | 惰性地址被越帧读取 (帧不变量被破坏) —— **恒为 0 才是对的**, 非 0 直接报我 |
| `代理 活跃 N 连接 · 上行/下行累计 · 背压触发` | 活连接求和 | 连接关掉即消失, 天然按会话 |

> **快照有两条来源**: 60s 周期, 以及**断开前强制一条** (`VpnController.disconnect` 里
> `emitDataPlaneSnapshot(force = true)`, 紧跟在 `正在断开 VPN 连接...` 之后, 在拆 TUN/SSH 之前取样)。
> 后者是必需的: 手测会话普遍只有 30~50s, 60s 周期一次都打不出来 → 资源节 / 闸门等待 /
> 地址惰性失效 / 在途通道 全都看不到 (2026-10-18 三段真机日志就是这样, 一条快照都没有)。
> 断开前那条**不含** `故障归因` 节 (紧接着就是完整的那一行, 不重复)。
> 判读纪律: **计数类只看"两条快照之差"**, 因为有些是进程累计; 瞬时 gauge 只看"收敛到什么值"。

## 3. 场景清单

每个场景给 (做 / 必看 / 不得出现)。"快照"均指日志里以 `数据面快照 · ` 开头的那一行
(每 60s 一条, **外加断开前必有一条**)。

### S0 · 冷启动基线 (每轮必跑, 也是其它场景的对照)

- **做**: 强杀应用 → 冷启动 → 连接 → 静默 90s (不操作) → 导出日志 (先不导出, 留到场景结束一起导)。
- **必看**:
  - `隧道连接成功` 或 `隧道通道就绪` 出现, 建连耗时 < 2000ms;
  - 静默期至少 2 条 `数据面快照`, 两条之差: 上行/下行接近 0 (后台心跳), `TCP 连接 0`;
  - `SSH 会话 3/3 (健康 3, 可疑 0, 在途通道 0)` —— 在途通道静默时必须是 0;
  - `SSH IO 线程 a/b (上限 128) · 饱和回执 0 次` —— **饱和回执必须是 0**;
  - `TUN 写队列 0` · `闸门等待 0` · `假 IP 映射 n/16384` (n 是小数, 不是几千) · `地址惰性失效 0`;
  - `故障归因` **整节不出现** (无 WARNING/ERROR); **例外**是偶发的
    `网络探测失败 · 隧道通道 — reason: tunnel closed with 0B before status line (请求后 Nms)`
    (2026-10-18 实测 1 次/会话; **2026-10-19 实测 1 次与 4 次** —— 端点服务器侧
    IPv4/IPv6 各 12/12 `204` 已排除, 见第 4 节该行);
    回报时写明次数和**紧跟的 `隧道通道空转关闭 · … 客户端已交 NB`** (那条给出方向), 别只回次数。
- **不得出现**: `饱和回执` > 0; `TUN 写队列` 持续 > 0; `假 IP 映射` 单调爬向 16384;
  `连接异常 · ` 行 (说明连败 2 次真的降级了, 那时 `网络探测失败` 也就不是"偶发"了)。

### S1 · 浏览 (TLS 短连接 + DNS 假 IP)

- **做**: 依次打开 8~10 个 HTTPS 站点 (含一个视频站首页), 等待全部加载完。
- **必看**: 每条连接的 `TCP 连接结束 ·<域名> — ... · 上行 xB/下行 yB · 存活 Nms` 都有非零下行;
  `故障归因` 为空; `假 IP 映射` 在页面关掉后**回落**(宽限期 60s 后才摘除, 故可能滞后一条快照)。
- **不得出现**: `假 IP 映射失效 · host:port 无域名映射, 已秒拒` (0x03); `本地代理无响应`;
  `隧道侧零回程`; `隧道无回程`; WARNING 级 `SOCKS 非阻塞切换失败`
  (常态的"握手刚完客户端就 RST"已降为 DEBUG 文案 `SOCKS 非阻塞切换跳过`, 默认不可见)。

### S2 · 大文件下载 (窗口闸门 + 回程缓存 + 背压)

- **做**: 浏览器下载一个 ≥ 50MB 的文件到完成。
- **必看**: 下载期间两条快照的 `下行` 差额 ≈ 文件大小 (允许 ±10%);
  `回程闸门阻塞` 只在小增量范围 (不能几分钟内涨到几百秒);
  `TCP 连接` 在结束后回落, `在途通道` 回落。
- **不得出现**: `回程缓存溢出` / `回程窗口耗尽` 大量出现; `上行背压丢段` 单调暴涨
  (少量 + 客户端重传能自愈是可接受的, 但它必须**不是**伴随"下行停滞"出现)。

### S3 · HTTP/2 多路复用 (同一域名并发多连接 → 假 IP 引用计数)

- **做**: 打开一个单域名并发很多请求的页面 (图墙/长列表), 让它跑完。
- **必看**: `假 IP 引用 n` (在 `TCP 连接 ... · 假 IP 引用 n ·` 段) 随连接数上升、关闭后回落;
  `假 IP 映射` 不出现"同一域名被分配多个假 IP"式的暴涨。
- **不得出现**: `假 IP 池耗尽`; 大量 `目标映射失效(0x03)`。
  > 这条锁的是"假 IP 必须按活动连接数配对释放"——单条 TCP 关闭就删映射会让并发请求拿 0x03。

### S4 · Play 商店下载安装 (历史故障场景)

- **做**: Play 商店安装一个 20MB+ 的应用, 直到安装完成。
- **必看**: 下载阶段 `下行` 持续增长; `TCP 连接结束` 里 CDN 域名 (`rr*---sn-*.googlevideo.com` /
  `*.gvt1.com` / `xn--ngstr-lra8j.com`) 有非零下行。
- **不得出现**: 某 CDN 域名 `隧道侧零回程 · host:443 — SSH 写出 517B / 读回 0B` (517B = TLS
  ClientHello, 即服务端方向不通 → 大概率又是服务器侧 IPv4 路由问题, 见 AGENTS.md 该条)。
  > 若出现: 先在服务器上按 AGENTS.md 的 `gai.conf` 小节复查, 别改 app。

### S5 · 视频播放 (长连接 + 持续大流量 + 抖动)

- **做**: 播一个 1080p 视频 3 分钟 (中途暂停/继续各一次)。
- **必看**: `下行` 持续增长; 暂停期增量回落但不为 0 (预缓冲); `零回程 0(秒断 0/迟断 0)`。
- **不得出现**: `隧道无回程 · ... 已写 NB / 读回 0B` 反复出现 (单次抖动可容忍, 同一域名反复即失败)。

### S6 · 网络切换 (自动重连 + 会话/线程不泄漏)

- **做**: 连接状态下 WiFi ↔ 移动数据 切换 2 次 (每次等状态显示已恢复)。
- **必看**: 每次切换有重连日志, 之后 `SSH 会话 3/3`; `SSH IO 线程` 回落到小数;
  **跨切换前后 `SSH 会话` 的分母不变 (恒为 3)** —— 变了就是会话池重复建。
- **不得出现**: `SSH 会话池整池重建` 反复; `SSH IO 线程` 长期顶到 128; 重连后 `在途通道` 只增不减
  (泄漏: 通道关闭路径漏了 `activeChannels` 递减)。

### S7 · 息屏 30 分钟后解锁 (keepAlive + 往返探活)

- **做**: 连接状态息屏 30 分钟 → 解锁 → 直接浏览 (不做别的)。
- **必看**: 解锁后首次 `隧道通道就绪` 建连耗时 < 3000ms; 若发生重连, 只发生一次 (不是循环)。
- **不得出现**: `SSH 会话未连接` / `往返心跳失败` 之后**没有**任何恢复行 (池被整体判死又没重建);
  `隧道插件启动失败`。

### S8 · 白名单模式 (空名单 / 非空名单各一次)

- **做**: (a) 白名单模式 + 一个应用都不选 → 连接 → 浏览; (b) 选 1 个应用 → 重连 → 用该应用浏览。
- **必看**: (a) 打 `白名单为空 · 所有应用均直连` 或 `白名单未启用 · 全部应用流量走隧道`
  (取决于模式, 二者之一是 INFO 不是 WARNING); (b) `白名单生效`.
- **不得出现**: 空名单时出现 `假 IP 映射` 分配 (空名单必须退化为 SYSTEM 解析, 否则直连被黑洞,
  表现为 `DNS_PROBE_FINISHED_NO_INTERNET`)。

### S9 · 白名单增删触发的 TUN 重建

- **做**: 连接状态下反复 加/删 白名单应用 3 次 (每次等状态稳定)。
- **必看**: 每次重建后仍有 `隧道通道就绪`; `故障归因` 不出现 `TUN 接口重建失败`.
- **不得出现**: `VPN 接口重建失败`; 重建后 DNS 变黑洞 (S8 的 (a) 判据)。

### S10 · 连接/断开循环 ×3 (会话边界清零 + 无跨会话残留)

- **做**: 连接 → 浏览 1 个页面 → 断开, 重复 3 次。
- **必看**: **每次断开前**必有一条 `数据面快照 · ` (强制那条) 且 (有故障时) 紧跟一条 `故障归因`;
  第三次的快照计数与第一次同量级 (**不是累计**); `TCP 连接 0`。
- **不得出现**: 新会话刚连上就显示上一个会话的累计值 (跨会话残留); 断开后 `代理 活跃 N 连接`
  仍 > 0 (本地代理连接未回收)。

### S11 · 高并发建连 (SSH 通道打开预算 + 坏会话后置)

历史故障 (2026-10-18 真机日志): `SSH 通道打开失败 · www.google.com:443 — channel is not opened.`
之后 3s 客户端拿到 `rep=5`, 而同一时刻别的连接建连只要 60~100ms。根因是候选预算被算成
"份额即总预算" —— 首个候选吃满 3s 后预算耗尽直接 `break`, 后面两个健康会话**一次都没试过**。

- **做**: 打开一个会并发几十条连接的东西 (新闻/图墙/应用商店首页), 连续两个页面跑完。
- **必看**: 建连时间线稠密时 `SOCKS 建连偏慢` 只占少数; 若出现 `SSH 通道打开失败 ·`, 它必须带
  `试了 N/M 个候选 · 末次耗时 Xms · 在途通道 K`:
  - `N/M` 越接近 M 越好 (说明确实逐个试了);
  - `Xms ≈ 3000` = 等不到 `OPEN_CONFIRMATION` (会话读线程被堵 / 服务器还没把目标连上);
  - `Xms` 只有几十~几百 ms = sshd **秒回** `OPEN_FAILURE` (目标不可达, 与本地栈无关)。
  > **2026-10-18 真机解析完这条分支的完整因果链** (Play 下载 + YouTube, 3.5 分钟内 ~200 条连接里
  > 只出现 1 次): `SSH 通道打开失败 · rr3---sn-q4fzen7r.googlevideo.com:443 — channel is not opened.
  > · 试了 3/3 个候选 · 末次耗时 131ms` —— 该节点名在 **8.8.8.8 与 1.1.1.1 上都是 NXDOMAIN**
  > (同族 `sn-q4fzen7y`/`sn-q4fl6nsl`/`sn-hgn7rn7y` 全部 NOERROR, VPS 的 `/etc/resolv.conf`
  > 也是正常 systemd-resolved 软链), 即 Google 交给客户端的节点名**在全局 DNS 里就不存在**。
  > 链路: 假 IP 模式**不查上游直接就答** (`DnsInterceptor` "走隧道: 不做真实 DNS 解析, 分配假 IP"),
  > 所以这个不存在的名字照样拿到假 IP → 客户端 CONNECT → sshd `getaddrinfo` NXDOMAIN →
  > **秒回** `CHANNEL_OPEN_FAILURE` → `createDirectChannel` 返回 null → `rep=5`。客户端当场换节点重试,
  > 同一批次 `gvt1.com`/`googlevideo.com` 正常下完 5~27MB (单条最大 26MB, clean EOF)。
  > 结论: **秒回分支 = 目标/服务端侧, 不要动本栈**; 假 IP 模式的固有代价是"不存在的名字不会以
  > NXDOMAIN 回给客户端, 而是变成一次快速失败的 CONNECT + 客户端重试"(~200ms)。
  > 判据补充: 同一批次里 `试了 3/3` 本身就证明候选预算没退化 —— 老 bug 的形态是 `试了 1/M`。
- **不得出现**: `试了 1/3 个候选` 且 `末次耗时 ≈ 3000` (说明"逐个尝试"又退化了);
  同一批候选在 30s 内反复出现 `通道打开失败` (stall 后置失效 → 越坏越优先)。

## 4. 判据总表 (阈值速查)

| 指标 | 通过 | 失败信号 |
|---|---|---|
| `饱和回执` | 0 | 持续增长 (池 128 成瓶颈 → 阻塞操作跑在 eventLoop) |
| `TUN 写队列` | 0~2 抖动 | 长期 = 上限 (写线程卡在 TUN 写) |
| `闸门等待` | 0 | 长期 > 0 且 `回程闸门阻塞` 猛涨 (客户端 ACK 停摆) |
| `在途通道` | 空闲时 0, 重度使用后回落 | 只增不减 (通道关闭路径漏减) |
| `SSH 会话` | 3/3 健康 | 分母 ≠ 3 / 健康 < 3 且无重建 |
| `SSH IO 线程` | 远小于 128 | 长期顶 128 |
| `假 IP 映射` | 远小于 16384, 页面关掉后回落 | 单调爬到 16384 |
| `孤儿包` | 少量 fin/ack | data 分类持续增长 (真丢包 / 连接过早清理) |
| `上行缓存累计` | 无阈值 (与 `下行` 一起看) | **不是 backlog** (累计 = 本会话进入缓存的总字节)。它涨而 `下行` 停滞 = 上行被卡; 此刻真正卡住的量看 `上行等待通道 · <域名> — (state=…, 队列 NB)` 那行 |
| `零回程` | 0 | 增长, 且伴随 `隧道无回程` / `隧道侧零回程` |
| `地址惰性失效` | 0 (进程累计, 不随会话清零) | > 0 (惰性地址被越帧读取 = 解析器帧不变量被破坏) |
| `回程缓存溢出` | 0 | > 0 (回程数据真的丢了) |
| `SSH 通道打开失败` | 不出现 | 出现且 `末次耗时 ≈ 3000ms` + `试了 1/M 个候选` (候选预算退化; 见 S11) |
| `SOCKS 非阻塞切换跳过` | 默认不出现 (DEBUG) | 出现 WARNING 版 `非阻塞切换失败` = 非"socket 已关闭"的成因 (socket 留在阻塞模式) |
| `故障归因` | 不出现 | 出现且不是你已知的那一个故障 |
| `网络探测失败` | 整节不出现; **单次偶发可容忍** | 同会话 ≥2 次 / 每会话都有 (连败 2 次会真降级成 `连接异常 · <步骤>`)。判读两种成因: 同一时刻**没有** `隧道侧零回程` = SSHD 通道连请求都没写出就 EOF (`toTunnelTotal==0`); **有** `隧道侧零回程` = 本栈回程/隧道问题, 要查。`0B before status line` 那一支**必须**与下一行的 `隧道通道空转关闭` 配对看才判得下去 (2026-10-19: 只有探测那行 + 服务器端点 24/24 正常 = 判不出方向, 才补的下一行) |
| `隧道通道空转关闭` (2026-10-19 新增) | 不出现 | SSH 通道**先于本栈**关闭且 0B/0B (探测 0 字节 EOF 的现场都是它)。看 `客户端已交 N`: `N>0` = 请求已进本栈却没写出通道 → 通道打开即被远端/sshd 关 (目标侧, 别动本栈); `N==0` = 客户端本就没发东西。两条一起报我 |
| `网络探测失败 · … timeout at http` | 不出现 | 一次性请求卡死 (要等满 4s) —— 见下一行 |
| 一次性请求卡死 (探测 / 单条 GET 永久无响应) | 不出现 | `网络探测失败 · … timeout at http` (**要等满 4s 才失败**) + 同一时刻**没有** `隧道侧零回程`(上行压根没写出本栈) + 所有丢弃计数为 0 = 上行卡在**通道就绪窗口** (Connecting 期间读到 `buffer` 里再没人处理; 见 AGENTS「Connecting 窗口的上行纪律」, 已修, 复现即回归)。**区别**: 同形态但"首字节 EOF 且很快失败" = VPS 出口/目标侧瞬时, 不动 app |
| 建连耗时 | < 1500ms | > 1500ms 且占比高 (`SOCKS 建连偏慢` 反复) |
